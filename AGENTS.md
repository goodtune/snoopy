# Notes for contributors and agents

`README.md` is the single user-facing document (what Snoopy is, install,
flags, endpoints, security, mobile app, release secrets). This file covers how
the repository is put together and the conventions to follow. Do not
duplicate README content here.

## Layout

| Path | What lives there |
| --- | --- |
| `server/` | Go module root (`go.mod`, `main.go`, tests, `.golangci.yml`, both units and example configs); one module, two binaries |
| `server/main.go` | `realMain`/`run`, Avahi advertisement (pure `advertisedServices`, `txtRecords`; one entry group), ffmpeg frame extraction (publishes each frame to a `frameHub`), image cache, HTTP handlers (`newHTTPHandler`) |
| `server/rtsp.go` | Optional RTSP stream: `rtspConfig`, `frameHub`, encoder selection (`parseEncoders`, `encoderCandidates`), `ffmpegArgs`, access-unit splitters, supervised encoder (`rtspStreamer.supervise`), gortsplib server handler |
| `server/config.go` | Flags and their `SNOOPY_*` env defaults (`envDefaults`, incl. `bool`), managed mode (`loadManagedFile`, pure `resolveConfig`) |
| `server/record.go` | Screencast loop (`recordLoop`, `rotate`, `screencaster`), restart/backoff and stall detection |
| `server/events.go` | Session events (`sessionEvents`): lock/unlock, resume, screencast `Error`, from D-Bus signals |
| `server/snoopy.service` | systemd **user** unit, installed to `/usr/lib/systemd/user/`; reads optional `EnvironmentFile`s `/etc/snoopy/snoopy.conf` and `%h/.config/snoopy/snoopy.conf` |
| `server/snoopy.conf.example` | Commented `SNOOPY_*` settings; packaged to `/usr/share/doc/snoopy/` and at the tarball root |
| `server/internal/envfile` | Parser for systemd `EnvironmentFile=` syntax, shared by the recorder (managed file) and the attestor (`attest.conf`, recorder config) |
| `server/cmd/snoopy-attest/` | Attestor CLI: `run`, `keygen`, `pin`, `check`, `-version`; exit 0 ok, 1 runtime error, 2 usage/config error |
| `server/internal/attest/` | Attestor config (`SNOOPY_ATTEST_*`), checks (`checks.go`), state machine (`state.go`), service loop, frame check |
| `server/internal/attest/{procfs,logind,pki,heartbeat}` | Injectable `/proc` reader (+ `procfstest` fake trees), logind client, device key/cert and SPKI pin, heartbeat v1 client |
| `server/snoopy-attest.service` | systemd **system** unit, installed to `/usr/lib/systemd/system/`, never enabled by the package; reduced capabilities and sandbox |
| `server/attest.conf.example` | Commented `SNOOPY_ATTEST_*` settings; packaged to `/usr/share/doc/snoopy/` and at the tarball root |
| `docs/attestation.md` | Attestor threat model, checks, states, **normative heartbeat protocol**, runbook; packaged to `/usr/share/doc/snoopy/` |
| `scripts/` | nfpm post-install (prints how to enable; never enables) / pre-remove (global disable on erase) scripts |
| `.goreleaser.yaml` | Release build (`dir: server`, builds `snoopy` and `snoopy-attest`): tar.gz, rpm, deb; changelog disabled |
| `mobile/` | Flutter app; platforms: android, ios, macos. Code in `mobile/lib/{models,screens,services,widgets}` |
| `assets/`, `mobile/assets/` | Images, stored in Git LFS (CI checkouts use `lfs: true`) |
| `.github/workflows/` | `server.yml`, `mobile.yml` (CI), `release.yml` (tag-driven release) |
| `renovate.json` | Renovate dependency updates (gomod, pub, gradle, GitHub Actions, Flutter version) |

## Build and test

Server (run from `server/`):

```bash
gofmt -l .                 # must print nothing
go vet ./...
go build ./...             # both binaries
go test -race -count=1 ./...
golangci-lint run          # v2 config in server/.golangci.yml, whole module
go run . -version
go run ./cmd/snoopy-attest -version
```

Running the server for real needs a GNOME Shell session on the D-Bus session
bus; tests must not depend on one. Use `-addr 127.0.0.1` when trying it out.
`snoopy-attest check` needs root on a real desktop; tests never do.

Mobile (run from `mobile/`):

```bash
flutter pub get
dart format --set-exit-if-changed .
flutter analyze --fatal-infos
flutter test
flutter build apk --debug
```

Packages: `goreleaser check` and
`goreleaser release --snapshot --clean --skip=publish` from the repo root.

CI mirrors these commands; keep them passing locally before pushing.

## Conventions

- **Conventional Commits** (`feat:`, `fix:`, `sec:`, `perf:`, `docs:`,
  `test:`, `ci:`, `chore:`). Release notes are generated by GitHub
  (`gh release create --generate-notes`), not by GoReleaser.
- **Docs follow code.** When you add or change a flag, env var, endpoint,
  mDNS TXT record, file location or package contents, update `README.md` in
  the same change (configuration table, API table, install steps).
- **Segment rotation** (`recordLoop`/`rotate` in `server/record.go`): GNOME
  Shell refuses a second screencast from the same D-Bus client, so the server
  holds two session-bus connections and starts the next segment on the idle
  one before stopping the current one (overlap, no gap). If that start fails
  it falls back to stop, `-pause`, start on the same connection. The loop is
  tested through the `screencaster` interface with fakes; keep it that way
  rather than requiring a live GNOME session.
- **Session events** (`server/events.go`): locking makes GNOME Shell kill
  screencasts and refuse new ones until unlock (sources cited in
  `events.go`). The loop consumes `sessionEvents` (`evLocked`,
  `evUnlocked`, `evResumed`, `evScreencastError`): it never starts while
  locked (also at startup, via `GetActive`), and on unlock/resume starts a
  fresh segment at once with backoff (`recoverDelay` doubling to
  `retryDelay`). The D-Bus source matches signals by well-known sender so
  other session processes cannot fake a lock. Failing to subscribe is not
  fatal (log, carry on). Test new behaviour with `fakeEvents`, never a live
  session.
- **Stall detection**: `-stall-timeout` (default `5m`, `0` disables)
  restarts a segment whose file size and mtime have not changed for that
  long while unlocked, checked on the health-check tick, at most once per
  timeout. Output is damage driven (with a 1 s pipewire keepalive) and
  buffered, so do not make it aggressive. The file stat is injectable
  (`loopConfig.stat`).
- **Exit codes**: `realMain` returns 0 on SIGINT/SIGTERM, 1 on errors
  (including D-Bus loss, after stopping the screencast and withdrawing the
  Avahi record via deferred cleanup) and 2 on invalid flags or `SNOOPY_*`
  values. Do not call
  `os.Exit` or `log.Fatal` inside `run`; it would skip the cleanup.
  `Restart=on-failure` in the user unit relies on the status-1 exit.
- **systemd unit**: `WantedBy=graphical-session.target` with `PartOf=` and
  `After=` on the same target, so it only runs in graphical sessions. Do not
  switch back to `default.target` (SSH/TTY logins would restart-loop).
  `ExecStart=/usr/bin/snoopy` takes no arguments; configuration comes from
  the `EnvironmentFile=` lines.
- **No auto-enable**: package scripts must not enable the unit (enabling
  screen recording is the administrator's choice). `postinstall.sh` only
  prints instructions; `preremove.sh` still runs `systemctl --global disable`
  on real removal (guarded by `$1` and `|| true`).
- **Env fallbacks**: every flag's default comes from `SNOOPY_<FLAG>` (flag
  name upper-cased, `-` to `_`) via `envDefaults`, so `-help` shows the
  effective default. Precedence: flag > env > built-in. Invalid env values
  exit 2. A new flag needs its env default (in `resolveConfig`), a line in
  `server/snoopy.conf.example` and a row in the README configuration table.
- **Managed mode**: if `/etc/snoopy/snoopy.conf` (path is the unexported
  `managedConfigPath`, never a flag or env var) sets `SNOOPY_MANAGED` true
  and is root-owned and not group/world-writable, that file plus built-in
  defaults are the only source: env and flags are ignored (names logged).
  Precedence is "managed file > nothing else". Wrong ownership or mode logs
  a warning and runs unmanaged; invalid values exit 2. The decision lives in
  the pure `resolveConfig` (unit-tested with synthetic uid/mode); the file is
  parsed with `snoopy/internal/envfile` from the opened descriptor. Keep both
  `EnvironmentFile=` lines in the unit.
- **Loopback by default**: `-addr` defaults to `127.0.0.1`. `shouldAdvertise`
  skips the Avahi advertisement for loopback binds (`127.0.0.0/8`, `::1`,
  `localhost`); exposing on the LAN is `SNOOPY_ADDR=0.0.0.0` in a conf file.
- **RTSP stream** (`server/rtsp.go`, off unless `-rtsp`): optional, and it
  must never take recording down: a missing ffmpeg/encoder or a busy port is
  logged and `run` carries on. One `ffmpeg` child (image2pipe JPEG in,
  `m4v`/`h264` elementary stream out) is supervised with backoff and killed
  through the deferred `Close`; snoopy splits its output at start codes and
  packetises it with gortsplib onto its own `ServerStream` (kept across
  encoder restarts while the codec parameters match). Nobody may publish
  (ANNOUNCE is refused). `OnRequest` maps every URL to one canonical path so
  `rtsp://host:port` works for VLC's mDNS module; digest checks use the
  original URL. The password is applied after flag parsing so `-help` never
  shows it, and it must never appear in logs or errors. What gets announced
  is the pure `advertisedServices` (unit-tested); integration tests use the
  real ffmpeg/ffprobe and skip without them (CI installs ffmpeg).
- **Version**: injected at link time (`-X main.version=...`, plus `commit`
  and `date`); `snoopy -version` prints it and the same value is advertised
  in the mDNS TXT record `ver=`. Clients must treat `ver` as informational
  and not compare it to a fixed value.
- **Attestor (`snoopy-attest`)**: the checks are pure functions over
  injectable `procfs.FS`, a logind `SessionSource` and a clock
  (`attest.Checker`); test them with fake `/proc` trees from
  `procfs/procfstest` and fake sessions, never requiring root, a system bus
  or a GNOME session. `TrustedUID` stands in for root in tests.
- **Heartbeat protocol**: `docs/attestation.md` is normative for heartbeat
  v1 (fields, pin format, responses, timing, reasons). Any change to
  `server/internal/attest/heartbeat` (or to the reason list in
  `internal/attest/checks.go`) must update that document in the same commit.
- **Attestor unit**: the package installs `snoopy-attest.service` but never
  enables it; `postinstall.sh` may only `daemon-reload` and `try-restart`
  (restart if already running), `preremove.sh` disables it on real removal.
  Do not add logic that restarts users' recorders after an upgrade.
- **Managed-mode agreement**: the recorder decides managed mode in
  `server/config.go` (`parseManagedSwitch`, `resolveConfig`: root-owned,
  regular file, not group/world-writable, `1`/`true`/`yes`); the attestor
  re-checks the same file in `server/internal/attest/checks.go`
  (`managedSwitchOn`, `checkRecorder`), along with the default output dir
  (`~/.cache/snoopy/video`), video extensions (`.webm`/`.mp4`, mirroring
  `findMostRecentVideo`) and unit name (`snoopy.service`). Keep them in
  agreement; `TestParseManagedSwitchTable` and
  `TestManagedSwitchOnAgreesWithRecorder` pin the same truth table.
- Dependencies are updated by Renovate; do not add Dependabot config.

## Releasing

A single `vX.Y.Z` tag releases the whole monorepo:

1. `gh release create vX.Y.Z --target main --generate-notes` creates the
   tag and the GitHub release (notes generated by GitHub) and triggers
   `release.yml`.
2. GoReleaser appends the server artifacts and install instructions to that
   release (`release.mode: append`); its own changelog is disabled so the
   notes are not duplicated.
3. The `android` job then builds the APK with `--build-name` from the tag and
   uploads `snoopy_<version>_android.apk` to the same release. It signs with
   the `ANDROID_*` secrets when present (see README), otherwise the APK is
   debug-signed.

Pre-1.0, minor versions may change flags and endpoints; call this out in the
commit message (`feat!:` / `BREAKING CHANGE:`).
